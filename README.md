# Are We Playing? (ABE League Match Days)

A non‑profit, open‑source app focused on delivering a better UX to explore match days for several universities in the ABE league. We aggregate data from third‑party APIs and present it in a clean, fast, and accessible interface.

> [!NOTE]
> We are not affiliated with ABE or any university. Data is fetched from public endpoints and may change without notice.

## Why this exists

- Provide the match days of several ABE‑league universities in one place.
- Offer a friendly, fast, and mobile‑first UX over raw third‑party APIs.
- Keep the project open‑source and community‑driven, with transparency around data sources.

## Features

- Browse every tournament of the current season (Division I/II, Varonil/Femenil, by conference).
- Match days by week, plus today's, upcoming, and past matches.
- Standings table and top performers per tournament, and a page per team with its schedule and results.
- Match detail pages with a countdown, a per‑match social card, and a shareable 9:16 story image you can download.
- Mark matches as favorites (stored in your browser) and jump straight to them.
- Light/dark theme, Spanish‑language UI.
- Old UUID‑based URLs redirect to their current slug.

## Tech Stack

- Astro `@7` (Vercel adapter, mostly prerendered + server islands)
- Preact `@10` via `@astrojs/preact` (`compat` mode, so React‑targeting libs work)
- Tailwind CSS `@4`
- TypeScript `@5`
- Biome (lint + format, including the JSON data files)
- `satori` + `sharp` for the per‑match Open Graph images
- Python `@3.13` + `uv` for the data pipeline

## Data Sources

We fetch data from third‑party endpoints and persist JSON snapshots under `src/assets/<TOURNAMENT_ID>/`, one folder per tournament listed in `src/assets/tournaments.json`:

- Match days: `https://scoretdi2025-eta.vercel.app/api/jornadas?torneoID=<TOURNAMENT_ID>`
- Matches by match day: `https://scoretdi2025-eta.vercel.app/api/partidos?jornadaID=<MATCH_DAY_ID>`
- Teams: `https://scoretdi2025-eta.vercel.app/api/equipos?torneoID=<TOURNAMENT_ID>`
- Standings: `https://scoretdi2025-eta.vercel.app/api/tablaResumen?torneoID=<TOURNAMENT_ID>`

Team logos come back as base64 and are resized and written as AVIF to `public/logos/`.

These files are the app's data source at build time — the site reads them, never the API.

## Going Easy on the API

The upstream API is someone else's server, so the pipeline is built to ask it for as little as possible. Nothing in the app ever calls it: visitors only ever hit our own JSON snapshots, and every request to the API comes from `scripts/populate.py`.

That script runs once per build and once a night at 00:00 (Mexico City), and before hitting the network it checks, per tournament:

- **Finished tournaments are never refetched.** Once a tournament is marked `finished` in `tournaments.json`, it's skipped for good. The flag is set by the script itself, when every match has an end time and two weeks have passed since the last match day.
- **Nothing is refetched twice within 24 hours.** Each tournament carries an `updated_at` in `tournaments.json`; if less than a day has gone by, it's skipped.
- **Static data is fetched once and then reused.** Teams and their logos don't change mid‑tournament, so they're read from the cached `teams.json` instead of being downloaded again. Weeks are reused too, and only refetched once the calendar runs out of future match days.

So a nightly run on an active tournament costs one request per match day plus the standings, and a finished or recently updated one costs nothing at all.

Both checks can be bypassed when you need to: `-f` / `--force` ignores the `finished` and 24‑hour guards, and `-s` / `--refresh-static` re‑downloads the weeks and teams. Use them sparingly.

## Getting Started

### Prerequisites

- Node.js `>= 22.12`
- Package manager: `pnpm` (the repo pins it via `packageManager`)

Only needed to run the data script (`pnpm populate`):

- Python `>= 3.13`
- [`uv`](https://docs.astral.sh/uv/getting-started/installation/) — install with `curl -LsSf https://astral.sh/uv/install.sh | sh`

### Install

- `pnpm install`

### Run locally

- `pnpm dev` → starts Astro at `http://localhost:4321`

### Build & preview

- `pnpm build` → production build
- `pnpm preview` → serve the built site locally

### Lint & format

- `pnpm lint` → `biome check`
- `pnpm format` → `biome format --write`

## Fetching Fresh Data

To refresh the local JSON snapshots:

- `pnpm populate` → runs `uv run scripts/populate.py`

Useful flags (see [Going Easy on the API](#going-easy-on-the-api) for what they skip):

- `-f` / `--force` → refetch every tournament, ignoring the `finished` and 24‑hour guards.
- `-s` / `--refresh-static` → re‑download the data that rarely changes (weeks and teams).

This script is written in Python, so it requires Python `>= 3.13` and `uv`. You don't need to create a virtualenv or install anything by hand: `uv` reads `pyproject.toml` and resolves the Python version and dependencies on the first run.

A GitHub Action (`.github/workflows/update-data.yml`) runs it every night at 06:00 UTC (00:00 in Mexico City), formats the result with Biome, and commits it only when the data actually changed — which in turn triggers a new deployment.

Tips:

- Be mindful of third‑party rate limits and availability.
- Lint/format the Python script with `pnpm py:lint` and `pnpm py:format`.

## Deployment

- Deployed on Vercel with `@astrojs/vercel`. Pages are prerendered; the adapter only serves the server islands (today's matches, top performers), the social cards, and the legacy‑URL redirects on demand.
- Each deployment serves a single season, selected with the `SEASON` environment variable (`src/constants/season.ts`): the current one on the main domain, past ones on their own subdomain.
- The data in `src/assets/` ships with the build, so make sure it's up to date before deploying.
